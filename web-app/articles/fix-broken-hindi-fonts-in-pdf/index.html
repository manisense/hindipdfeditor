Hindi Text Broken in a PDF? 4 Different Problems and How to Fix Each One

"Hindi is broken" can mean four very different things, and the fix for one does nothing for the others. Start by matching what you see on screen to one of the four cases below.

By Manish · Updated 25 September 2026 · about 6 minutes to read

Quick diagnosis

Matras jump to the wrong side while editing → your editor isn't shaping Devanagari (case 1). Empty boxes (□□□) → the font wasn't embedded (case 2). Looks right, copies as gibberish → a broken text map inside the PDF (case 3). English letters like "d`fr nso" → a legacy Kruti Dev–style font (case 4).

Case 1: Matras jump around as soon as you edit

You open a Hindi PDF in an editor, click into a line, and the moment you type, "कि" becomes "क ि", the reph in "धर्म" wanders off, and half-letters split apart. This is the most common complaint, and Acrobat users have been reporting it on Adobe's own community forum for years.

Why it happens: Devanagari isn't written one character after another. The short-i matra is typed after the consonant but drawn before it; "क्ष" is three characters that become one shape. Turning typed characters into the right shapes is called shaping. When a PDF editor re-flows existing Hindi text without a proper shaping step, it puts each character in typing order, and the word falls apart.

How to fix it:

  • If you still have the Word or source file, make the change there and export a fresh PDF. This is always the cleanest fix.
  • If you only have the PDF, don't edit the Hindi line in place. Cover it and type the new line on top, in a tool that shapes Hindi the way a web browser does. Hindi PDF Editor works this way: tap the line, type the replacement in Unicode Hindi, and the browser's text engine joins every matra and conjunct.
  • Before you print or submit, zoom in on names and words with conjuncts, such as श्री, क्ष, त्र or द्ध. That's where mistakes hide.

Case 2: Empty boxes instead of Hindi letters

The PDF shows □□□ or blank space where Hindi should be, often on one computer or printer but not another.

Why it happens: The file refers to a Hindi font but doesn't carry the font inside it. Your device doesn't have that font, so it falls back to one with no Devanagari letters.

How to fix it:

  • Ask for, or re-export, the PDF with fonts embedded. In Word: File → Options → Save → Embed fonts in the file, then save as PDF.
  • Stick to Unicode fonts like Noto Sans Devanagari or Mangal.
  • If you can't get a new file, open it on a device that has the font (often a Windows PC with Mangal) and print to a new PDF from there. The new file carries the shapes.

Case 3: Looks fine, but copy-paste gives gibberish

The page reads perfectly, but when you copy a sentence into WhatsApp or Word you get jumbled letters or matras in the wrong order. Search inside the PDF doesn't find Hindi words either.

Why it happens: A PDF stores the shapes it draws separately from the text they stand for. The link between them is an internal table (the "ToUnicode map"). Many PDF generators write that table wrongly for conjuncts and matras, so the page looks right but the text underneath is scrambled.

How to fix it:

  • Go back to the source file if one exists. Its text is correct.
  • Otherwise use OCR that supports Hindi. Google Lens or Google Drive's "Open with Google Docs" both read printed Devanagari reasonably well. Then proofread, because OCR confuses similar letters like ब/व and ङ/ड़.
  • Don't try to fix it by editing the PDF: an editor that reads the same broken table will show you the same gibberish.

Case 4: "d`fr nso" instead of "कृति देव"

You see English letters and symbols that look like typing mistakes. This is a document typed in a legacy font such as Kruti Dev, DevLys or Chanakya. These fonts store Hindi shapes on English keyboard letters, so without the exact font the file shows the English letters underneath.

How to fix it: A Kruti Dev–to–Unicode text converter can turn the copied text into real Hindi, and you then re-create the document in a Unicode font. Hindi PDF Editor detects legacy fonts when you open the PDF. The web editor switches editing off on those pages, and the Android app offers a replacement mode where new words are added in a Unicode font. Neither converts the old text. Our Kruti Dev PDF guide covers this case in detail.

How to avoid all four next time

  • Type Hindi in Unicode (Google Input Tools, InScript or your phone's Hindi keyboard), not Kruti Dev.
  • Use Noto Sans Devanagari or Mangal, and embed fonts when you export.
  • Keep the source file. A PDF is for sharing, not for editing.

Other questions people ask

Why does Hindi look fine in the PDF but turn into gibberish when I copy it?

The PDF draws the right shapes but doesn't carry a correct map from those shapes back to Unicode letters. Copying reads that map, not the shapes. Nothing in the file can be edited to fix it cleanly; you need OCR or the original Word/source file.

Which Hindi font should I use so the PDF works everywhere?

Use a Unicode font such as Noto Sans Devanagari (free) or Mangal (bundled with Windows), and make sure fonts are embedded when you save the PDF. Avoid Kruti Dev and other legacy fonts for anything you will share.

Does Hindi PDF Editor fix copy-paste gibberish in my file?
