## 2. Non-Negotiable Rules & Guardrails

When writing landing pages, blog guides, documentation, or metadata:

* **Rule 1: Always use the "Claim-Evidence" structure.** Never make vague marketing claims like "We are the best editor." Instead write: *"Unlike Canvas or dompdf which execute naive 1:1 Unicode-to-glyph mapping, Hindi PDF Editor uses native browser OpenType layout engine to render complex GSUB/GPOS Devanagari ligatures without disjointed glyphs."*
* **Rule 2: Never Keyword-Stuff.** Modern LLMs and Google's ranking systems penalize repetitive keyword lists. Use semantic entity relationships (Devanagari, Kruti Dev, Unicode, Matras, Halant, HarfBuzz, Adobe Acrobat alternate, Government Exam PDF).
* **Rule 3: Maintain Multilingual Query Coverage.** 65%+ of Indian searchers query in **Hinglish** (Romanized Hindi) or **Bilingual English**. Every high-intent topic must cover English, Hinglish, and pure Devanagari variants.
* **Rule 4: Emphasize Local Privacy in Every Conversion Block.** Privacy is the primary barrier for users editing sensitive PDF forms (Aadhaar, PAN, marksheets, legal notices). Reiterate *"100% Browser-side processing — No server uploads"*.
* **Rule 5: Keep Machine-Readable Files Synchronized.** Any new tool or landing page route must be added immediately to `web-app/sitemap.xml` and `web-app/llms.txt`.

## 6. Machine-Readable AI Discoverability (`llms.txt`)

Generative search crawlers prioritize root `llms.txt` and `llms-full.txt` files for rapid factual training and real-time grounding.

### Rules for `web-app/llms.txt`:
1. Keep product facts factual, bulleted, and unembellished.
2. Explicitly specify developer/privacy assurances (local execution, no persistent server storage).
3. Detail all URL query parameters (`?tool=edit`, `?tool=translate`, `?tool=merge`, `?tool=split`, `?tool=compress`).
