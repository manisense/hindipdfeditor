Prepared 1 October 2026; updated the same day after the user confirmed the landing-page redirect now leads to `/`. Scope: planning and audit; no production changes made by this task.

Detailed implementation authority: [final SEO, design and web experience implementation plan](SEO_IMPLEMENTATION_PLAN_FINAL_2026-10-01.md). ## 1. Decision and target

Concentrate on becoming the most useful Hindi PDF editing result for Indian users. Make `/` the primary landing-page owner and preserve the search signals accumulated by the former `/edit/` landing page, improve the few pages already attracting impressions, and substantiate the product's Devanagari expertise with real examples. Spend approximately 60% of initial effort on core editing, 25% on demonstrated supporting demand, and 15% on measurement and relevant editorial visibility. These are planning allocations, not measured ROI.

Target #1 for the core cluster in India, separately on mobile and desktop. Define success as sustained first-position visibility for an agreed keyword set plus successful organic exports. A single personalized search or a sitewide average position is not proof of #1. Neither technical fixes nor a publishing schedule guarantees rankings.

## 5. Technical implementation specification

1. Export GSC URL Inspection evidence for key pages: indexability, Google-selected canonical, last crawl, rendered resources. Verify production robots/sitemap with actual HTTP requests; inspect coverage and manual/security actions.
2. Build a URL inventory including all public pages, parameter states, old locales and alternate hosts. Use `/` as the landing-page owner. Include its final HTTPS URL in the sitemap and remove the old bare `/edit/` if it redirects. Update navigation, article links, canonical tags, social URLs and structured-data landing-page URLs consistently. Preserve useful tool URLs according to their actual distinct behavior; do not redirect every tool query to a generic homepage.
3. Sitemap contains canonical, indexable final URLs only. Remove LLM text files from the SEO sitemap unless there is a specific indexing purpose. Use genuine last-modified dates; `priority` and `changefreq` are not a growth strategy.
4. Distinct tools may later receive clean static landing URLs, but launch only with unique useful content and a tested migration map from old parameter URLs. Do not release thin placeholder pages or break bookmarks/file workflows.
5. Use stable language-specific URLs for actual Hindi translations. A localStorage language toggle alone does not establish two independently discoverable pages. Keep `/hi/` until its existing role and selected canonical are understood; no automatic deletion.
6. Measure mobile field performance if available: good thresholds at the 75th percentile are LCP ≤2.5s, INP ≤200ms, CLS ≤0.1. Small traffic may mean insufficient field data; report that and use lab diagnostics separately. Audit editor, article and tool templates. Investigate initial PDF/OCR bundles, animated hero visibility, fonts and image dimensions; existing lazy tool imports are a useful starting point. Do not claim a speed problem without measurements.
7. Analytics events carry tool type, success/failure category and coarse supported context only. Never send document text, file names, personal fields, PDFs or page images to analytics. Confirm GA4 events once per successful action and export-success only after output validation. Do not pretend GSC query-level users can be joined directly to GA4 conversions.

### Homepage migration acceptance and monitoring

- `/` is the core SEO landing page; serve substantive initial HTML, HTTP 200 and canonical `https://hindipdfeditor.com/`.
- The former bare `/edit/` landing page should use a permanent 301 or 308 to `/` if it is now retired. Maintain that redirect for at least a year and preferably indefinitely while old links remain useful. Verify the actual status rather than assuming the user’s redirect change establishes it.
- Audit `/edit/?tool=edit`, `translate`, `merge`, `split` and `compress` separately. Keep working distinct tool destinations or redirect to equivalent new tool routes while preserving intent. Do not strip their query state indiscriminately.
- Remove obsolete `/` → `/edit/` rules from the deployed configuration. Check for loops, multiple-hop chains and client-only redirects. Align internal landing-page links and sitemap with `/`; tool links retain their actual functional destinations.
- Inspect `/` and the old landing URL in GSC; request indexing for the updated homepage once it is validated. No domain Change of Address request is needed for this same-domain path move.
- Record the actual deployment date as the migration boundary. Compare equal completed periods and track the combined core landing-page cluster across old and new URLs, separately from distinct tools. A fall in `/edit/` clicks accompanied by a rise at `/` is expected redistribution, not by itself traffic loss. Track query-level visibility and successful organic exports to detect real loss. Do not blindly add page impressions as a deduplicated site total.
- Review weekly until Google’s selected canonical and visibility stabilize. Investigate sustained combined visibility/export declines; do not reverse the migration solely because the historical winning URL loses clicks.

## 8. Measurement and decision rules

Weekly dashboard: India Web clicks/impressions/CTR by page and query cluster; average position by country/device; indexed canonical pages; organic tool opens; validated exports; export failures; translation completion; mobile performance. Separate brand-like `hindi pdf editor` queries from more clearly non-brand intent, acknowledging the phrase is both generic and the product name.

First 30 days: complete measurement and correct confirmed issues. Days 60–90: seek improved visibility for selected clusters and increased successful organic exports; set numerical growth targets after the exact baseline and prior-period trend are available. #1 remains a longer-term competitive target, not a 90-day promise.

At fixed impressions, improving Parimarjan CTR from 2.82% to 5% would yield roughly 12 clicks instead of 7; affidavit from 2% to 5% roughly 13 instead of 5. Together this is only approximately 13 additional clicks for the supplied period, not a major growth forecast. Growing relevant visibility and task completion matters more than snippet tweaks alone.

Review rules: positions 4–15 with relevant impressions → deepen content, product evidence and links; good position with weak CTR → inspect the actual SERP and title/intent; poor indexing → fix crawl/render/canonical issues first; clicks up but exports flat → investigate workflow rather than publish more content. Use a page-specific, device-specific CTR benchmark; no universal “good CTR.” Wait for recrawl and adequate samples. With this traffic, run sequential documented changes rather than low-power split tests. Consolidate pages only after query-page overlap confirms redundant intent.

## 9. Required follow-up data

Exact start/end dates and property chart totals; matching preceding period; complete query/pages/country/device exports with average position and search type; query-to-page exports for priority clusters; index coverage and sitemap status; inspected canonicals for `/`, `/edit/`, `/hi/`, HTTP root and parameter tools; migration deployment date and actual redirect status codes, including parameter-route handling; real mobile performance; GA4 organic conversion baseline; product limits and currently supported font/export behavior.
